# Reducing repeated X-Node work

## Member inventory and live metrics

Combo, PAYG and hourly inventory previously loaded the same groups, node,
configuration and snippets for each exported endpoint/principal. Hourly
inventory also built clients before rejecting endpoints outside its group.
Routing preparation uses the same member inventory path.

One inventory/metrics invocation now owns its topology and decoded-input
projection. Group bindings filter unrelated endpoints before credential and
client projection. Every output retains independent account, stream and group
fields. New calls reread storage; financial and member eligibility decisions
are not retained across requests. Subscription publication and owner fences
are unchanged.

## Hourly credit scheduling

A completed scan previously kept `work` true whenever any unfinalized
reservation existed, even when it had already been delivered. Continuing
activity hints could also repeat day creation and row locks on every
100-millisecond scheduler tick.

Quiet scans and already checked demand now recheck once per second. New demand,
committed consumption, receipt acknowledgments, retirement, recovery and
unfinished pages remain immediate work. The existing bounded workers,
fairness, failure backoff and authoritative ledger checks remain in place.
A fresh held-byte read can avoid opening a credit-day transaction when even
the maximum possible target is already amply covered. This shortcut cannot
issue credit or charge a member.

## Routing GeoSite selection

The GeoSite cache previously had one entry keyed by the source configuration
and the current member's selected categories. Alternating plans with different
category sets evicted one another and repeatedly downloaded, parsed and
validated identical source data.

The cache retains up to 32 selection entries within a 16 MiB accounting budget.
Verified domain slices shared by the same source, content hash and selector are
counted once across combinations. Source generation changes invalidate related
expansions and publish a compile revision. Cold failures use bounded retry
backoff; verified same-key stale data retains its existing refresh-failure
behavior. Caller cancellation is not cached. Oversized results retain a refresh
fence without retaining their full expansion.

Source/hash validation, native selector validation and failure isolation remain
in place. The existing serialized outbound request queue performs asset loads.
This cache contains no member access or routing authorization.

## Validation

The repository prohibits local automated suites. Local validation uses build,
formatting and static analysis; targeted regressions and the existing race,
PostgreSQL, memory, routing and CPU-profile gates run in hosted CI. Added
regressions cover bounded inventory reads and fresh eligibility, isolated client
credentials, quiet-credit polling and urgent work, and GeoSite reuse,
concurrent refresh, source invalidation, failure isolation and memory bounds.

There is no schema migration, additional aggregate ledger, index change or
billing-policy change. PAYG rolling evidence and settlement queries remain
unchanged. A proposed cutoff-query rewrite was excluded because its plan could
still scan and sort the retained window without a reliable improvement.

After rollout, compare the deployed commit, comparable active workload,
CPU-counter intervals, SQL call rates, pool waits and traffic commit/ACK metrics.
Keep the previous image and persistent volumes for rollback; never run a
second scheduler against the live database. Production measurements belong in
private operational records rather than repository documentation.
